## Credit Offer Flag Boundary

The Android `render` gate reads bytes 1, 2 and 3 of `dword_218230` plus both
bytes of `word_218234` (five offers after a reserved byte). `OnTouchEnd`
uses the same five-offer completion condition, and `RecordHandler` reads and
writes the fifth flag. The six-slot boundary correction was made here first.
The later options-record binding, including the credit-menu flag at
`byte_218236`, is documented in
`HANGAR_CREDIT_FLAGS_PERSISTENCE_ARM_2026-10-31.md`.

## Item Row Ordering

The Android `render` body routes selected Store/Blueprint amount buttons and
column headers into the amount-string body before its common item price/icon
path. The prior C++ placed both after the icon. The accepted C++ now follows
the native order. Its pending-product row also creates an empty quantity
prefix when count is below two, as the Android String lifetime does. Separate
`Ship::getIndex`, `BluePrint::getIndex` and `Item::getIndex` queries are retained
at their distinct native text/icon/marker call sites instead of reusing one
cached value. These changes raise `render` from 88.5% source / 8.7% strict to
89.1% / 17.9%; they do not establish byte identity.

## Upgrade-Mode Station Copy Evidence

In the original `render` at `0x149a44..0x149a5e`, the second price-display
branch calls `Ship::getPrice` on both the shop hull and the active hull,
subtracts them into `r2`, and passes that difference to
`Layout::formatCredits(int)`. The upgrade-mode branch instead formats the
full shop price. The previous C++ reused the full price in both branches.

The Android `HangarWindow::OnTouchEnd` branch at `0x14da6c..0x14da82` loads
`Status+0x14c` (`voidStation`) into `r5`, calls `Status::getStation()->getShips()`
for `r1`, places `1` in `r2`, and calls
`Station::setShips(Array<Ship *> *, bool)` with `r0 = r5`. This is a deep copy
to a different station object, not a self-assignment of the live station list.
The typed C++ path now follows those three arguments. The focused comparison
increases `OnTouchEnd` source-shape from 92.0% to 92.3% and call-count
agreement from 99.1% to 99.7%; it is still not linked- or byte-exact.

The original `render` branch for a pending product at `0x14a500..0x14a532`
loads `GameText` ID 275, constructs a single-space String, joins those two
Strings, then joins the result with the String at `ListItem+0x18`. That pointer
is `PendingProduct *`, whose first field is `stationName`. The recovered C++
now draws this second line in grey and restores white before the item icon.
The extracted Android body also clears the normal label after drawing the
last blueprint slot's action button. These two changes raise focused `render`
source-shape from 87.5% to 88.2%, while strict similarity is 8.5% rather than
8.9%; no byte-match is claimed.

The original blueprint row calls `BluePrint::getCompletionRate` at
`0x1496ba` and again at `0x1496d2`. Its label construction at
`0x1497c2..0x149818` joins the integer percentage, `"%  ("`, the String at
`BluePrint+0x14` (`stationName`), and `")"`. The first-pass C++ omitted the
station and closing parenthesis and cached only one completion query. Both
are restored. The Android selected-item branch also calls
`TouchButton::getWidth` for the station-side action even when its amount is
zero and the button stays hidden, preserving the inspector's right offset.
Focused `render` source-shape rises from 88.2% to 88.5% and strict similarity
from 8.5% to 8.7%.

## Item Amount Scope And Footer (2026-09-26)

Android `HangarWindow::render` around `0x149e..0x14a4` limits the
`getCurrentTab() == 1 || (tab == 4 && isItem())` test to the selected row's
amount buttons. The selected row always draws its amount-column headings;
selected and nonselected item rows both enter the shared amount-text block.
For tab 1 it uses station/current amounts; otherwise it uses current plus
blueprint-completion amounts. The previous C++ put headings and amount text
inside the action-button gate. The corrected scope preserves the original
store/blueprint distinction. Its first focused form lowered `render` from
89.6%/17.9% to 88.7%/7.8%, but it was retained for proven behavior.

The explicit Android branch join (`LABEL_109/LABEL_110`) and separate left/
right unit-String lifetimes bring `render` back to 89.5%/18.3%. Repeating
`Item::getIndex()` at the blueprint current-amount query reaches 89.6%/18.3%;
